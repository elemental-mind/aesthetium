Tokens

Aesthetium uses a three-tier token system built entirely on CSS custom properties. Understanding it lets you customize every aspect of the framework without touching the source.

How Tokens Work

Tokens flow in one direction:

Design tokens  →  Semantic tokens  →  Component tokens
  • Design tokens — raw values (colors, sizes, families)
  • Semantic tokens — purpose-mapped aliases (--color-text, --color-bg)
  • Component tokens — element-specific overrides (--btn-radius, --input-border)

Override at any tier. Changing a design token propagates everywhere that semantic and component tokens reference it.

Customization

Add a :root block anywhere after the framework stylesheet:

<link rel="stylesheet" href="aesthetium.css">
<style>
  :root {
    --color-accent:    #6d28d9;
    --color-accent-fg: #ffffff;
    --font-body:       'Inter', sans-serif;
    --radius:          0.75rem;
  }
</style>

Component Tokens

Component tokens let you override individual element styles without affecting the broader system:

:root {
  --btn-radius:      var(--radius-full);   /* pill buttons */
  --input-radius:    0;                    /* square inputs */
  --card-padding:    var(--space-8);       /* roomier cards */
  --header-height:   4rem;                 /* taller nav */
}

Dark Mode & [dark]

Dark mode activates automatically via prefers-color-scheme: dark. Semantic tokens remap to dark-mode values — no extra code needed.

The [dark] attribute forces a dark surface on any element regardless of the OS setting:

<section dark>
  <h2>Always dark</h2>
  <p>This section uses the dark palette.</p>
</section>

Default surface

Follows the OS theme.

Dark surface

Always uses the dark palette.
